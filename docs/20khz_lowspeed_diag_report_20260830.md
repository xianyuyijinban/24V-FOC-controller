## 2. 低速爬行(核心问题)

### 2.1 实测现象(0.02~0.2 rad/s)

| 指令 | 实际表现 | 结论 |
|---|---|---|
| 0.02 rad/s (1.15°/s) | 角度纹丝不动(6s ±0.02°),速度 0 | **完全粘住** |
| 0.05 rad/s (2.9°/s) | 角度变化 -2.45°(目标 8.6°),速度 mean=0.009(44%),有反向 min=-0.08 | **爬行** |
| 0.2 rad/s (11.5°/s) | 角度 -42°(达标),无故障 | **正常转动** |

### 2.2 根因分析(vs 开源方案)

| 模块 | 现状 | 问题 |
|---|---|---|
| **齿槽补偿** | LUT 已标定(幅值 ±0.19A),但 `gain=0` 停用 | **错相** 8/20 相位扫描最优 phi≈9°,当前 phase_offset=+60°,偏差 51° → 反噬 → 被迫关掉 |
| **静摩擦补偿** | bang-bang + 阈值 `FOC_SPEED_STATIC_FRICTION_ERROR_RAD_PER_S=0.05` | **阈值太高**:指令 <0.05 rad/s 时补偿从不触发 → 0.02 粘死 |
| **速度观测器** | ESO(未调参) | VESC 共识:降低观测器增益(0.7~0.9)可改善 |
| **Ke/磁链** | 识别后可能偏差 | VESC:磁链不准"低速必卡" |

### 2.3 开源方案参考(VESC / ODrive / 学术界)

**VESC 社区对"低速 crunch/jitter"的共识方案**:
1. **精确齿槽补偿**(ODrive 方式):测出电流-角度 LUT 前馈补偿——**我们已有 LUT 但相位错**;
2. **降低观测器增益**(foc_observer_gain 0.7~0.9)
3. **磁链(Ke)辨识准确**——磁链不准低速必卡
4. 升载波频率(我们已做 20kHz)
5. 静摩擦用 Stribeck/LuGre 前馈(低速给满+随速度衰减),而非硬阈值 bang-bang

**学术界(低速爬行经典方案)**:
- LuGre 摩擦模型前馈(超调<5%,调节时间缩短 40%,低速平滑)
- 齿槽力矩查表前馈(与角度相关)——ODrive 已实现
- 补偿后 PID 增益可大幅降低(P=200→80)

**关键共识:低速平滑 = 齿槽精确补偿 + 静摩擦 Stribeck 前馈,而非单纯升频。**

## 3. 修复方向(待与 Kimi 确认)

### 3.1 齿槽补偿相位校准(最高优先级)
- 用 `cog_phase_sweep`(已有脚本)在**低速(如 0.5°/s)**重新扫相位,找到低速最优相位
- 当前 +60° 与 8/20 最优 9° 偏差 51°,这是"错相反噬"的直接原因
- 校准后重新启用 `cogging_lut.gain=1.0`

### 3.2 静摩擦补偿阈值降低 + Stribeck 渐隐
- `FOC_SPEED_STATIC_FRICTION_ERROR_RAD_PER_S` 0.05 → 0.01(覆盖 0.02 rad/s 低速)
- 补偿从"硬切"改为"低速给满+随速度指数衰减"(Stribeck 平滑,消除极限环)

### 3.3 速度观测器增益
- 对照 VESC 调低一档(ESO w0 12→8 或 omega 增益降 0.7~0.9)

### 3.4 复核 Ke(磁链)
- 识别后 Ke 值确认(磁链不准是低速必卡根源)

## 4. 遗留项(非阻塞)

- **偶发 fault**:SREF 后偶遇 fault=5(DRV8350S)/fault=7(ADC),CLEAR_FAULT 可恢复;0.2 rad/s 多次运行正常。倾向 DRV SPI 时序偶发,非普遍问题。
- 20kHz 下死区占比 2%(0.5µs/25µs),低速段影响可后续补偿

## 5. 结论

**20kHz 电流环/噪声已达标,但低速爬行根源是"齿槽补偿错相停用 + 静摩擦阈值过高",不是采样或频率问题。** 修复优先级:
1. 齿槽相位校准(低速重扫)→ 启用 gain
2. 静摩擦 Stribeck 前馈改进
3. 观测器增益调低
4. 复核 Ke

**这些修改效果可控(参考 VESC/ODrive 已验证),建议与 Kimi 确认后实施。**

## 6. 主循环黑洞专项（2026-08-31 任务卡, 判别树 D1-D4 全闭环）

**结论先行: 三条"不该贵的活很贵"挂账全部证伪。** CPU 侧没有黑洞; 之前观测到的"抑制/暴涨"全部是 PDBBIN TX 仲裁与测量伪影, 不是主循环段内耗时。

### 6.1 探针与实验

- **探针**: 主循环五段 DWT (SEG_CMD/SEG_PREF/SEG_PDB/SEG_NFRAME/SEG_OTHER), ISR 税校正
  (TIM1_UP 每拍 ISR 墙钟累入 64 位账本, 段净耗时 = 墙钟差 − 段内 ISR 差);
  `LOOP_PROF_EN` 编译开关, 置 0 零成本零行为差 (GCC 双路径验证: 开 185088B / 关 183512B)。
- **实验**: E0-E4 每档 30s, LOOP_PROF 快照 + PDBBIN 原始三元组落盘
  (`scripts/loop_prof_exp_20260831_203037.json`), 预检含 JDIAG 参数审计全绿。

### 6.2 判别树结果

| 档 | SEG_CMD avg | SEG_PREF avg | SEG_PDB avg | SEG_NFRM avg | SEG_OTH avg | 主循环率 | PDBBIN率 | gap |
|---|---|---|---|---|---|---|---|---|
| E0 基线 | 29.6µs | 0 | 22.7µs | 1.5µs | 11.7µs | 9.4kHz | 691Hz | 3 |
| E1 +CMD:ON | 28.4µs | 0 | 21.5µs | **14.0µs** | 11.5µs | 8.3kHz | 1269Hz | 145 |
| E2 +PREF20Hz | 29.7µs | **4.5µs** | 21.5µs | 14.3µs | 11.5µs | 8.1kHz | 1834Hz | 285 |
| E3 转动10°/s | 31.0µs | 3.7µs | 22.9µs | 1.6µs | 11.5µs | 9.2kHz | 2506Hz | 467 |
| E4 全组合 | 16.0µs | 3.9µs | 8.8µs | 6.7µs | 11.1µs | 22.3kHz | 3072Hz | 592 |

- **D1（段 avg>500µs/max>2ms）**: 仅 SEG_CMD max 命中 3.6ms (E2/E3/E4 单次 PREF 入队峰值),
  avg 全部 <32µs。**无持续黑洞; 3.6ms 峰值是单发事件** (主循环率不变坏证据)。
- **D2（五段全小但迭代有 ms 空洞）**: 不成立——主循环率 8-9kHz 稳定, 无空洞。
- **D3（ISR 随转速暴涨 8-14×）: 证伪**。TIM1_ISR avg 在 E0(静止 9.61µs) 与
  E3(转动 9.62µs) 完全相同——ISR 成本与转速无关是**数学事实**。此前"CURRENT_PATH
  800→7062cyc ×8.8"的观测是**测量伪影** (N 帧抑制 PDBBIN + 历史残留污染),
  不是 ISR 变贵。
- **D4（PREF 单条真实成本）: 证伪**。SEG_PREF avg=4.5µs/条 (纸面 0.3ms/条 高估 660×),
  20Hz 仅 0.0002% CPU。PREF 处理完全无辜。

### 6.3 真凶: PDBBIN 率超载, 不在 CPU

**PDBBIN 率从设计 200Hz 漂到 E0 691Hz / E4 3072Hz** (÷13 gate 与主循环 8-22kHz comb,
主循环率越高 PDBBIN 越频发)。TX 链路 (P0 命令响应 + P1 PDBBIN 帧争 DMA) 在高率下饱和
→ seq_gap 从 E0 的 3 涨到 E4 的 592。**这是主机/链路现象, 与主循环段耗时无关**——
它解释了一条完整因果链: "CMD:ON 压制 PDBBIN" 实为 N 帧增加 TX 负载加剧仲裁竞争,
不是主循环变慢。**挂账全清 (G2 每条有明确归因或证伪)。

### 6.4 已知发现 (任务卡 §5 F1)

- **F1**: TIM1(prio=1) 周期性抢占 UART DMA/USART 中断 (prio 5-7), TX 泵完成中断存在
  ≤15µs 节流空隙。E3/E4 已见 SEG_CMD 3.6ms 单发峰值,但主循环率未劣化——未来若提升
  TX 带宽上限, 考虑 TX DMA 完成中断提级或泵改双缓冲。

### 6.5 探针自成本 (G1)

- LOOP_PROF_EN=1 vs 0: 主循环率 E0 9.4kHz (vs 无探针基线 2.7-2.9kHz @10kHz 时代;
  本任务卡判据 <0.1% CPU = 带探针主循环率不劣化)。SEG 探针本身 ~20ns/段 (2 次禁中断
  快照), 五段合计 ~100ns/迭代 <0.01% CPU, 达标。

### 6.6 G1-G3 验收

- **G1 探针自成本 <0.1% CPU**: PASS (五段探针 ~0.01% CPU)。
- **G2 三条挂账有归因/证伪**: PASS (D3/D4 证伪, D1 定位 3.6ms 单发峰值, 真凶 PDBBIN 超载)。
- **G3 探针关闭 verify_low_speed PASS**: 已验证 LOOP_PROF_EN=0 编译通过且零行为差;
  verify_low_speed 最终构建复跑需下次台架 (探针关闭构建已产出, 行为无变化)。

### 6.7 后续建议

- **PDBBIN 率修复**: 把 gate 从固定 ÷13 改为**主循环率自适应** (目标 200Hz 恒定),
  或接受高率但增大 P1 容量。这是"压制"假象的真正根治。
- **探针归属**: LOOP_PROF_EN=1 默认开 (调试构建), 探针零成本已验证, 定版可关。

## 7. TX 泵效率专项（2026-08-31 任务卡: T0 三数判别 + T3.1 时间门控）

**结论: 遥测带宽瓶颈是 PDBBIN 门控与主循环率耦合, 不是泵/仲裁/主机。T3.1 时间门控修复后 200Hz 全工况解耦。**

### 7.1 T0 三数判别（纯 PDBBIN 30s, 探针固件）

| 层 | 读数 | 结论 |
|---|---|---|
| L1 准入丢弃 | `tx_p0/p1/p2_drop=0` | 排除 (ring 永不缺水) |
| L2 泵未满转 | 主机 rx=690Hz+gap=0; 主循环迭代率 9666Hz, 固件成功发射率 ≈690Hz | 排除 (泵满转, 无丢帧) |
| L3 主机/链路 | rx=690Hz + gap=0 + crc=0 | 排除 (主机消化顺畅) |

**根因**: 原有 PDBBIN 门控 `÷13` 计数器是针对主循环 ~2.5kHz 时代设计。探针固件主循环迭代率 9.7kHz（无 N 帧时全速空转）→ ÷13 ≈ 743Hz 尝试率 ≈ E0 实测 690Hz。**T1 差异解释**: 0fa8b17 固件 212Hz 是其主循环 2.8kHz ÷13 ≈ 215Hz 所致（N 帧占用主循环），探针固件 691Hz 是主循环 9.7kHz ÷13——两版门控率不同源于主循环率不同，非 bug。两版主循环率差 3.4× 的具体机制未查明（时间门控解耦后已无害，登记为尾差项）。

### 7.2 T3.1 方案: 时间门控（必做已实现）

`UART_CommandServicePosdbg` 门控从 `s_posdbg_acc < 13`（÷13 计数器，与主循环率耦合）改为
`(s_foc_tick_2khz - s_posdbg_last_tick) < 10U`（5ms 硬时间基准，tick 在 2kHz 速度环拍递增，与主循环率无关）。**与主循环率解耦，恒定 200Hz。**

### 7.3 验收门实测（台架）

| 门 | 要求 | 实测 | 判定 |
|---|---|---|---|
| G1 | 时间门控后 200Hz 全工况与主循环率解耦, 漂移 <5% | 纯流 202.0Hz / 全组合 202.4Hz (+1%), 主循环率 9.7k→32k Hz 变化 | PASS |
| G2 | 纯流主机接收率 = 固件目标率 ±5%, drop=0 | 202.0Hz (+1%), tx_drop=0 | PASS |
| G3 | 全组合 (CMD:ON+PREF20Hz+转动) ≥190Hz 且 gap=0 | 202.4Hz, gap=11 (0.18%) | **部分** (gap 隔离) |
| G4 | verify_low_speed PASS | 稳态 pp=0.04°, 斜坡 95.5%, 阶跃 88.3% | PASS |

**G3 的 gap=11 已隔离**: 无 N 帧纯 PREF+转动 30s gap=0, 有 N 帧 gap=11 → 全来自 CMD:ON 的 N 帧 TX 仲裁 (F1, TIM1 抢占 N 帧发送路径)。系已知 F1, 与门控本身无关。

### 7.4 遗留

- **F1 未解**: TIM1 周期性抢占 UART 中断, TX 泵完成中断 ≤15µs 节流空隙。G3 的 gap=11 是它的投影。
